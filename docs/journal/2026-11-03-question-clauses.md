# 2026-11-03 · M11 题目 → 条文级推荐

## 问题

「规范定位」按钮原来只按九大类打开规范清单；M4 虽然能从解析里抽条文，但只在
「错因建议」面板里显示，用户要先看解析才知道这题该翻哪。缺的是：
**打开一道错题，直接看到这题对应的规范、条文和页码。**

## 决定

1. **三种来源，按证据强度排序，不混成一个分数。**
   - `answer`：M4 已缓存的解析引用（标准号 + 条文），精确；
   - `prototype`：题目落在某个案例原型区间 → 伴读路线里该原型的站 → 该站条文；
   - `keyword`：章节名 / 2025 题干摘要 → 人工整理的「考点词 → 伴读站」表。
   每行在界面上标明来源；解析引用解析不到页码就进 `unresolved`，不猜。
2. **不重新造一套条文知识库。** 复用 M10 的 67 站（每站已有条文、页码、
   原型标签）和 `PROTOTYPE_RANGES`；只补一张约 60 个站的关键词表，专门填
   原型区间覆盖不到的题（如基础设计、公路/铁路、盐渍土等）。
3. **关键词只在本大类内匹配。** 大类加分；跨大类只保留两条明确链路：
   特殊土 → 边坡规范的滑坡条；检测 → 勘察规范的载荷试验条。
   去掉「基础埋深/防水/圈梁」这类会跨站误命中的泛词。
4. **这个接口不做 OCR。** 详情页的「错因建议」已经会暖 M4 缓存；点击
   「规范定位」只读缓存和本机索引，稳定在毫秒级；无缓存时退到原型/关键词。
5. **同一条文只出现一次。** 解析引用 5.2.4 与原型站 5.2 指向同一节时合并成一行，
   条文列表取并集，来源保留更强的「解析依据」。
6. **上限 5 条，页码全部来自本机索引。** 只有能打开页的条文才进列表；
   扫描件目录级索引解析到「节首页」而不是条文所在行，界面明确显示节标题和页码。

## 数据与实现

- `app/clauses.py`
  - `hints(qid)`：`answer → prototype → keyword` 合并、去重、排序；
  - `_stop_rows()`：把 9 本伴读路线展开为 `(规范, 节, 条文, PDF 页, 页数)`；
  - `_prototype_keys()`：`C3-11 → A1`，B4/B5 重叠时两个都保留；
  - `STOP_KEYWORDS`：人工整理的考点词；`CROSS_CATEGORY_GUIDES` 是唯一跨类白名单。
- `app/answer_ocr.py`：新增 `load_cached()`，只校验缓存版本，不触发 OCR。
- API：`GET /api/attempts/{id}/clauses`；异常时返回 200 + `error`，不阻塞详情页。
- 详情页「规范定位」改为展开面板「这题的规范位置」：
  每行 = 规范 + 条文 + 节标题 + 页码 + 来源；点击直达规范页图；
  底部保留「按大类看规范」旧入口；解析引用未收录时显示提示。

## 已知缺口 / 下一步

- 没有伴读路线的规范仍无推荐：盐渍土、冻土、基桩检测、压实/注浆、岩体分级。
  这些题会显示「没有可定位的条文」，回退到按大类看规范。
- `index/tags/A2025.json` 的题干只有 120 字，A2025 关键词推荐只能看开头，
  个别题可能不够准；M4 缓存命中后精确引用会排在最前。
- 页码到「节首页」，不是条文所在行；扫描件没有文字层，再往下需要条文级 OCR，
  投入产出低，暂不做。
- 反向索引（某条文 → 错题本里哪些题引用过）尚未做，可作为后续整理「考前依据清单」的入口。
