# M2 错题本 · 落库、批量记错、旧照导入、备份（2026-11-01）

目标不变：拍 → 做 → 对答案。M2 让「记错」真正落库，且用户数据与只读索引彻底分开（D5）。

## 数据形态

- `data/wrongbook.db`（SQLite, WAL）是唯一用户库；附件在 `data/attachments/`，
  备份在 `data/backups/`。索引仍只读，重建不影响错题本。
- **一题一行**（`attempts.qid UNIQUE`）：重复记同一题 → `times + 1`、刷新 `last_at`，
  不克隆行。列表天然去重；重做次数留给 M3 判定顽固题。
- 四类错因存**英文键**（concept / calc / standard / misread），中文只在前端映射；
  `attempt_tags` 支持一题多标签。
- 题号之外的展示信息（篇/节/书名）一律由 `app/catalog.py` 从 lookup + chapters 派生，
  不写进用户库，避免索引重建后两份数据打架。

## 照片与导入

- 上传照片：EXIF 转正 → RGB → 长边 ≤3200 → JPEG q92 存档，另生成长边 640 缩略图；
  **sha256 按原始字节去重**，同一张照片反复上传只存一份。
- 旧照片导入（`app/photo_import.py`）：文件名只在这里当提示；
  `4-12 4-13错.jpg` 解析出两条；预览给出 新/已在库/题库无此号 三种状态；
  提交时只插「新」题，重复导入是 no-op。
- 导入题的时间取 EXIF 拍摄时间（这批是 2026-03-11），不是导入时间。

## 接口（`app/server.py`）

```
POST /api/photos                   上传/去重照片
GET  /api/photos/{sha}?size=        原图/缩略图
POST /api/attempts {qids,tags,note,photo_sha,family}   批量记错（≤50）
GET  /api/attempts {family,tag,chapter,status,days,qid,limit,offset}  列表 + 全局统计
PATCH/DELETE /api/attempts/{id}    标签/笔记/掌握/删除
GET  /api/import/preview           旧照片预览（18 张 → 19 题）
POST /api/import {shas}            按勾选提交
GET  /api/backup                   下载整库 zip
```

- `/api/resolve` 现在带回 `attempt`（次数/标签/状态），查看页直接显示「错 N 次」。
- 批量接口对未知题号逐条报错，不整批失败。
- 空标签在批量记错里视为「不改动」，避免重记时抹掉已有标签；详情页 PATCH 可显式清空。

## 备份 / 恢复

- 备份：SQLite backup API 取一致性快照（不拷运行中的 db 文件）→ 与附件一起打 zip，
  带 manifest（题数/照片数）。
- 恢复：先 `PRAGMA integrity_check`，再给当前数据做一次安全备份，最后替换；
  **恢复前先删残留 `-wal`/`-shm`**，否则旧 WAL 会覆盖新库。

## 前端

- 顶部两个页签：查题 / 错题本；查题页保持 M1 原流程。
- 拍完整页后：勾题 →「记错」→ 底部表单（4 个错因标签、一句备注、附照片）→ 保存。
- 错题本：按册/篇/时间/掌握状态/错因过滤；标签计数来自全库统计；
  列表显示题号、篇·节、错次、最近日期、手写缩略图；点进详情可看题面/解析、原照片、
  改标签/笔记、标记掌握、删除。
- 快速连点筛选不会被吞：请求在飞时挂一个 pending，回来后补发一次。

## 验证

- **旧照片 19/19**：18 张 → 19 题（`4-12 4-13错.jpg` 两题），再导一次新增 0。
- **浏览器端到端**（`.probe/m2/check_flow.mjs`，390×844，临时库）：
  空库 → 导入预览 18 张可新增 19 → 导入 19 → 详情改标签/笔记落库 →
  批量勾 2 题带照片记错 → 过滤算错=1、已掌握=0 → 删除后 20。**PASS**。
- **200 条记录**（`.probe/m2/check_200.py`）：插入 0.013 s；各过滤查询 1.7–2.4 ms；
  重开库 200 条仍在；25 题批量 0.009 s；备份→恢复 225 条一致。
- 备份可恢复（真实库）：CLI 备份 19 题/18 照片 → 恢复到临时目录 → 19 题、C4-12 照片在。
- 单元测试 47 条全绿（含 store 过滤/幂等、目录映射、导入解析、备份恢复）。

## 踩到的坑

- `catalog` 的题号正则分组错位（把字母当篇号）——测试直接抓到。
- 旧照片缩略图在导入页显示成原图：`.item .mini` 作用域太窄，改成 `.mini`。
- 快速连点筛选：`loadBook` 在 loading 时直接 return，第二个筛选被丢掉 —— 改 pending 补发。
- 筛选无结果时空态文案误报「错题本还是空的」——改为按全库总数区分。

## 有意没做

- 不做场次/时间段（「时间不够」记场次）——归 M3 复习。
- 不做掌握自动判定（连续 2 次做对 + 间隔）——M3。
- 旧照片导入目前固定 C 族（这批全是案例册）。
- 预览会先落照片文件；取消导入的孤儿照片在下一次提交/删除时清理。
