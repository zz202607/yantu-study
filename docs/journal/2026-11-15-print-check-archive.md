# 一张卷闭环：打印 → 做完核对 → 自动归档

2026-11-15 · UX + data

## 症状（_ming 的要求）

每天就是打印要做的题 → 做完 → 拍照上传 → 选错因；其他自动归入错题。
"是不是新题，你自己知道啊，怎么要我来确定什么四个数？"

旧流程的问题不是多一个按钮，而是让用户重复输入 App 已经知道的事：

- 打印是无状态的，核对时又要用户自己找题、选题号；
- 新题/复习的划分只有用户脑子里有；
- 作答/做对/放弃/超时四个数要手填，其实可以从"哪些题没做对"反推。

## 决定

1. **打印即记账。** `scope=today` 生成 PDF 后写一条 `day_packs`：
   题号 + 角色（复习/新题）+ 冻结的复习会话。打印两次时，新的覆盖旧的未核对卷。
2. **核对只标例外。** 打开"做完核对"，所有题默认「对」；
   用户只把没做对的题点成「错」、选错因；「没做/超时」按需点；可拍一张卷面。
3. **归档全自动。**
   - 复习题：按冻结会话的队列顺序调用 `grade`，自动走 7/15/30 天排期；
   - 新题做错：自动建错题本记录（带错因、照片）；
   - 新题总量：自动生成一条练习台账（source=`paper`），四个数不用再填；
   - 照片：存到卷包，并挂到错题（复习题用 process photo，新错题用原图）。
4. **首页只剩两步。** 打印今天的卷 → 做完核对；没打印的日子走「直接在 App 里复习」；
   新错题仍可单独「拍题」记。四个数从首页路径移除。
5. **非 App 打印的纸面仍走拍题。** 一次拍一页、勾选、记错；不要求逐题录。

## 实现

- `app/store.py`：schema 10，`day_packs` 表；`save_day_pack` / `open_day_pack` /
  `latest_day_pack` / `close_day_pack`；练习来源新增 `paper`；attempt 来源新增 `paper`。
- `app/daypack.py`：`apply_results()` 归一化结果、按会话队列顺序评分、
  自动建错题与练习台账、汇总 warnings；未提交的题默认 correct。
- `app/server.py`：打印成功后 `save_day_pack`；`GET /api/day-pack`、
  `POST /api/day-pack/{id}/result`；`/api/home` 带 `day_pack`；打印复习队列时
  排除已评题，必要时冻结会话。
- `app/static/index.html`：首页改为「今天的卷」（打印 / 核对 / 已归档三态）；
  新增核对面板（分组、对/错/没做/超时、错因 chips、卷面照片）；
  移除四个数步骤与首页旧的四步列表。
- `app/briefing.py`：任务单的练习项在有今日卷时显示"自动归档"，不再催四个数。
- `docs/usage.md`、`README.md`：改成两步流程，补充"错题不用一题一题录"和
  "四个数自动算"。

## 限制

- 一个卷包只收一张卷面照片；逐题过程照仍可在错题详情或复习页补。
- "默认都对"假设这张卷确实做了；没做的题要手动点「没做」。
- 只有 App 打印的今日卷能闭环；外部纸卷、周包、错题卷仍按原流程。
- 同一题已在 App 内复习评过再核对，会按重复评分处理，排期不重复改。
- 非打印的练习仍需在计划页手动记四个数（不再出现在首页路径里）。
