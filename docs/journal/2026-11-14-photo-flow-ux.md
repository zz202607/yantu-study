# 拍题流程修正：日期误报、连拍、返回、超时归类

2026-11-14 · UX fix

## 症状（_ming 实测反馈）

1. 拍错题页时，页面顶部的日期会被识别成题号候选。
2. 拍完一题后，不知道怎样回到「再拍一张」。
3. 没有明显的返回上一层入口；误触返回直接退出 App，只能重新扫码/重拍。
4. 做错的题同时超时，不知道该归入四类错因里的哪一类。

## 决定

1. **日期在候选生成阶段就丢掉，不做前端过滤。**
   OCR 常把 `.` / `/` 读成 `-`，`2024-11-14` 会被拆成合法题号 `4-11`
   （年份尾部 + 月份）。只在前端隐藏的话，`auto_qid`、基准和手输校验
   仍会看到这个幽灵候选。新增 `DATE_RES`（`YYYY-MM-DD`、`YY-MM-DD`、
   `YYYY年MM月DD日`、`YYYY-MM`，覆盖 `-—–_./·` 各种 OCR 横线），
   候选匹配落进日期区间就丢弃；正常 `4-11` 标签不受影响。
2. **「拍下一张」直接打开相机，不再先回首页。**
   查看器和候选页都保留这个按钮；它只重新触发 `#camera`，取消拍照时留在原页，
   不会清掉当前照片和勾选。查看器里不再因多题模式隐藏它（多题时叫「下一题」
   容易和批量翻题混淆，所以统一叫「拍下一张」）。
3. **返回是三级：查看器 → 候选 → 拍题首页，然后才离开 App。**
   用一条 `history.pushState` 哨兵拦截手机返回手势：
   - 查看器里返回：回到候选，照片/勾选/当前阶段都在；
   - 候选里返回：回到拍题首页；
   - 首页再返回：才退出。
   记错弹层打开时，返回先关弹层（不把下面的页面带走）。
   页面左上新增「‹」和「‹ 返回」；首页新增「继续上次识别（N 题）」，
   即使真退回首页也能一键回到候选，不用重拍。
4. **超时不是错因，是速度/场次维度。**
   - 错题本仍只有四类：不会 / 算错 / 规范错 / 审题错；不加第五类「超时」，
     否则「不会」和「慢」混在一起，错因分布失真。
   - 基线四象限：`wrong` 优先于 `overtime`，做错 + 超时仍归「做错」；
     超时只单独计数，用来识别「做对但超时」的「会但慢」。
   - 限时拆解：时间到还没做完，结果是「超时」（不是错因）；
   - 因赶时间做错但做完了：按真实原因选（算错/规范错/审题错/不会）；
     纯粹没时间做完：留空，场次记超时，速度走限时拆解。
   - 记错弹层和复习错因行都加了这句提示，避免每次靠记忆判断。

## 实现

- `tools/recognize_qid.py`
  - `DATE_SEP` / `DATE_RES` / `_date_spans()`；
  - `qid_candidates()` 对 ANCHOR / LOOSE / BARE / BARE_STEM 四类匹配统一做
    `inside_date()` 过滤。
- `app/static/index.html`
  - 新增 `#resumePick`（首页）、`#pickBack`、`#viewerBack`；
  - `armBackGuard()` / `lookupBack()` / `popstate`：一条哨兵，查看器→候选→首页；
    记错弹层优先关闭；不新增/不重复 push；
  - `#retry` / `#again` 直接 `$("camera").click()`；查看器按钮改「拍下一张」并常显；
  - `updateResumePick()`：候选非空时首页显示「继续上次识别（N 题）」；
  - 记错弹层 + 复习错因行 + 基线记分抽屉补充超时归类提示。
- `tests/test_recognize_dates.py`：11 条日期守卫单测（完整日期、两位年份、
  中文日期、各种横线、`YYYY-MM`、正常题号不回归、非日期的三位粘连仍能拆分）。

## 验证

- **单测 296 条全绿**（新增 11 条日期守卫）。
- 18 张真图基准不回归：候选召回 **17/18 = 94%**、打包召回 17/18、
  auto-accept **6/6 = 100%**；平均 6.87 s、最慢 13.13 s。
- 无头 Chrome 390×844 实测返回链（脚本 `.probe/ux_back_check.js`）：
  - 查看器 → 返回 → 候选（候选 2 条仍在）；
  - 候选 → 返回 → 首页，首页出现「继续上次识别（2 题）」；
  - 点「继续上次识别」→ 回到候选；
  - 记错弹层打开时返回 → 弹层关闭、仍停在候选；
  - 宽度 0 横向溢出，JS 语法通过 `node --check`。

## 限制

- 不带年份的缩写日期（如 `4-11` 表示 4 月 11 日）与真实题号完全同形，
  没有可靠上下文可以区分；这次只保证带年份的日期不再误报。
- 返回哨兵只覆盖拍题流程（首页/候选/查看器）和记错弹层；其他 tab 的弹层
  仍按浏览器默认行为处理。
- 相机由 `<input type="file" capture>` 触发，取消后停留在原页面；这是浏览器
  文件选择器的行为，App 无法感知「已取消」。
