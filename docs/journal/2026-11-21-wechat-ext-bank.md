# 公众号每日作业：外题库 + 每周卷

2026-11-21 · 公众号题 / 外题库

## 需求（_ming）

「华山论剑岩土」公众号每天发每日作业，先发题、再发答案；想每周整理一次，
只收“案例”补充进自己的题库。用户明确：页眉写「2026年11月19日作业」这类页面
就按案例算，不再按有没有 A/B/C/D 选项区分。

## 抓取结论：文章不能自动抓

- 直接请求 `mp.weixin.qq.com/s?...`：返回「环境异常 / 验证码」页。
- 无头 Edge 打开同一 URL：仍是验证码页（不是 JS 能绕过的空壳）。
- 搜狗微信搜索能拿到标题（如 `3月17日每日一练/2026...`）和日期，但 `/link`
  最后落到 `wappoc_appmsgcaptcha`，正文和图片拿不到。
- 没有公开的公众号文章 API；第三方抓取要微信阅读号或付费，有账号风险。
  → 采用 **用户保存题图/答案图 → App 本地 OCR/裁剪/入库** 的半自动流程。

## 决定

1. **分类按用户口径。** 每天 `YYYY年M月D日作业` 的题图/答案图都记为 `case`；
   不再用 A–D 选项自动判“知识题”，避免误删用户想要的题。
2. **一天一对，题图/答案图都可多张。** 题图页和答案页分开存；答案是同一道题的
   解析页，不是第二道题。
3. **本地 OCR + 裁剪。** RapidOCR 读页眉日期/标题；题图裁掉页眉、页脚和大片空白；
   答案页从「解/答/【解析】」开始裁，去掉重复题干。答案页没有标记时保留正文。
4. **题号 `WYYYY-MM-DD-N`**，同一天多对自动 `-1/-2`；图片存
   `data/ext/<qid>/`（原图 + 裁剪 + 缩略图），元数据进 `ext_questions`。
5. **周卷独立生成。** 「打印未打印」→ 封面 + 全部题面 + 全部答案，题面和答案
   各自从 1 编号；生成后标记 `printed_at`，下次只打印新导入的；「重打全部」可重来。
6. **内容边界。** 只在本地 `data/`，不进 git、不上传；备份 zip 包含 `data/ext/`。

## 实现

- `app/extbank.py`（新）：OCR 行 + 几何裁剪、日期/标题提取、答案起点识别、
  原图/裁剪/缩略图落盘、周卷 PDF（A4、页眉页脚、答案封后、字体子集）。
- `app/store.py`：`ext_questions` 表（`SCHEMA` 自动建表）、
  `next_ext_qid/add_ext_question/ext_question/ext_questions/mark_ext_printed/delete_ext_question`；
  备份/恢复加入 `ext/`。
- `app/server.py`：`GET /api/ext`、`POST /api/ext/import`（multipart，线程池 OCR）、
  `GET /api/ext/{qid}/image/{q|a}/{n}`（原图/缩略图）、`GET /api/ext/print`。
- `app/static/index.html`：首页快捷入口「公众号题」；导入表单（题图/答案图多选）、
  「已整理」列表、查看器（答案默认收起）、打印未打印/重打全部。
- `tests/test_extbank.py`：日期/标题、答案裁剪起点、Store 往返、真实样本导入 + PDF。
- `docs/usage.md` / `README.md` / `docs/SUMMARY.md` / `PROGRESS.md` 同步。

## 限制 / 下一步

- 图片仍需在微信里手动保存；文章不能自动抓（验证码）。
- OCR/裁剪按 1080×1526 的作业页调；其他版式若裁不准，保留原图可重做。
- 目前是独立外题库 + 周卷；**错题本/复习联动未接**（合成 qid 已预留），
  下一模块再做「加入错题本 / 复习 / 统计」。
- 内容版权归培训机构，仅本地个人学习，不提交公开仓库。

## 更新（2026-11-21）：只存答案页 + 图片监听器

_ming 确认：答案页本身就有完整题目，只存答案页即可。另希望能把图片自动抓到一个
文件夹，少一点手动操作。

### 决定

1. **答案页一张图也能导入。** 在答案页里按「解 / 答 / 【解析】/【答案】」切成两半：
   题面 = 日期/标题到解答前，答案 = 解答到结尾。题图输入可以留空；接口只要求
   至少一张答案图。答案页里找不到解答标记时返回明确错误，不硬塞。
2. **三种导入入口**：
   - App 内选答案图；
   - App 内 Ctrl+V 粘贴剪贴板图片；
   - `tools/wechat_watch.py` / `wechat_watch.bat` 监听剪贴板和
     `data/wechat_inbox/`：微信右键复制，或另存到收件箱，自动入库。
3. **为什么不做浏览器插件**：微信文章页有验证码，内嵌浏览器也不加载扩展；
   剪贴板/收件箱监听不碰微信接口，用户看到什么就收什么，不违反访问限制。
4. **监听器去重与失败处理**：按 sha256 去重；成功后原图移到
   `data/wechat_inbox/imported/`，失败（例如不是含解答的答案页）移到 `failed/`
   并打印原因；`seen.json` 防止重复入库。监听器不删除用户自己的文件，复制文件
   先复制进收件箱再处理。

### 实现

- `app/extbank.py`：`_crop(stop_at_solution=True)`、`_save_answer_page()`；
  `import_pair()` 支持 `question_paths` 为空；答案页第一张切两半，额外答案页作续页。
- `app/server.py`：`question` 改为可选；只要求 `answer`。
- `app/static/index.html`：题目图可留空、粘贴区、粘贴计数与入库清理。
- `tools/wechat_watch.py`（新）：剪贴板 + 收件箱轮询、multipart 上传、去重、失败归档。
- `wechat_watch.bat`（新）：UTF-8 控制台启动器。
- `tests/test_extbank.py`：答案页答案从「解」开始、题面在「解」前结束；
  真实样本改为**只传答案页**的端到端测试。

### 验证

- 临时库只传 6400.png：导入 6.4 s，得到 `W2026-11-19-1`，q1/a1 两半；
  题面文字含题干与选项，答案文字从 `2.70×(1+0.258)`/`解` 开始；PDF 3 页 0.50 MB。
- 真实服务 `POST /api/ext/import` 只传 answer：5.4 s → `W2026-11-19-2`
  （测试项已删除，库里只保留用户样本 `-1`，未打印）。
- 监听器文件夹模式：`data/wechat_inbox/test-answer.png` → 自动识别 →
  `已入库：2026-11-19` → 原图移到 `imported/`；测试项与副本已清理。
- pytest **408 条全绿**。

### 限制

- 监听器用 `PIL.ImageGrab`，是 Windows 工具；需要先 `start.bat` 让服务在跑。
- 微信右键复制是否给出位图取决于客户端版本；不行就“另存为”到
  `data/wechat_inbox/`，文件夹模式一样会收。
- 只存答案页时，答案页必须含「解/答/解析」这类解答标记；否则会提示补一张题图
  或存含解答的答案页。
- 多页答案只切第一张（题目所在页），后续页作为答案续页。
