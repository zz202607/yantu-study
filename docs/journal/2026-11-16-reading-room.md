# 规范伴读：从「看双联缩略图」到「精读模式」

2026-11-16 · UX

## 症状（_ming 实测反馈）

伴读里的规范页字太小，看起来很费劲；点「全屏看」进入的弹层也只是把同一张图放大，
左右两联挤在一起，翻页还要退出再点，无法边看提示边读原文。

## 根因

多数标注版 PDF 的每一页不是一页规范，而是**同一印刷页的左右两联**（2-up），
内容是重复的（GB 50011 例外，见文末补记）：

```
[ 印刷页 p6 的左联 ][ 印刷页 p6 的右联 ]   ← 一张 PDF 页
```

旧流程把整张双联图放进 760 px 的栏宽，再按容器宽度缩放，
有效正文宽度只剩一半 → 正文 6–10 px。全屏弹层同样显示整张双联图，
放大只能整体放大，没有利用「左右两联内容相同」这一点。

## 决定

1. **页图接口按联裁切。** `GET /api/reading/{code}/{stop}/page?half=left`
   用 PyMuPDF 的 `clip` 只渲染一联：字号直接翻倍，而不是放大位图。
   dpi 上限 200 → 300；精读用 220，行内用 160；缓存按 `p<页>_<dpi>_l.png` 分开。
   干净版回退是正常单页，忽略 `half`，避免把单页裁掉一半。
2. **行内页默认单联。** 点图或「全屏精读」进入精读模式；行内仍可放大/翻页。
3. **精读模式 = 左要点、右原页。**
   - 左：站下拉（相当于目录）、为什么读、先看这些、条文 chips、最容易错、
     30 秒自检、同类题、笔记、需回看/看完了；
   - 右：220 dpi 单联原页，默认**按宽度铺满**（字最大、纵向滚动），
     「整页」按钮切全局视野；`+ / −` 缩放、拖动平移、双击放大；
   - 翻页：工具栏、`← →`、`PgUp PgDn`、跳页；翻的是整本标注版，不局限于一站；
   - 站间：顶部上一站/下一站，`Esc` 退出；预取前后页，翻页不等图。
4. **手机不另做一套。** <900px 时左栏变成「要点」抽屉，页面占满宽度；
   顶栏与工具栏自动换行/缩短，字号与桌面一致。
5. **精读里也能直接完成一站。** 保存后原地进入下一站；未保存的笔记在退出时带回行内。

## 实现

- `app/reading.py`：`annotated_page_at(..., half="")` / `annotated_page(..., half="")`；
  `HALVES` 白名单 + `clip` 渲染 + 缓存名带 `_l/_r`。
- `app/server.py`：读页接口加 `half` 参数，dpi 上限 300。
- `app/static/index.html`：
  - 行内 `readingPageUrl` 默认 `dpi=160&half=left`；点图开精读；
  - 新增 `#readRoom` 全屏浮层、`renderReadingRoom` / `renderReadingSide`、
    尺度计算（宽度铺满 / 整页）、缩放、拖动、键盘、预取、移动端抽屉；
  - `recordReading(status, noteOverride)`：精读内的笔记直接随保存提交；
    保存后精读原地切下一站；退出精读同步页码与未保存笔记。
- 文档：`docs/standards-reading.md` 增「精读模式」。

## 验证

- `pytest` **347 条全绿**（新增 3 条：单联宽度为整页一半、未知 half 回到整页缓存、
  站页接口接受 half）；真实页首次渲染 220 dpi 单联 ~0.24 s。
- CDP 无头 Chrome：1440×900 与 390×844 两档。
  - 行内页 936×1292（160 dpi 单联），精读页 1287×1776（220 dpi 单联）；
  - 精读左栏 9 站、翻页 p22→p23、125% 缩放、整页切换、手机要点抽屉、
    退出后行内页码同步，全部 PASS；0 JS 异常。
- 页面版本握手仍生效：`index.html` 改动会触发手机自动 reload。

## 补记：抗震规范只有左半页（同日修复）

首版上线后 _ming 实测发现 GB 50011 从 p20 起只剩左半页。根因是**批次内版式不统一**：

- 9 本标注版里 8 本是横版 2-up，**GB 50011 是竖版单页**；
- 首版对所有书都按 `half=left` 裁，竖版书就被裁掉右半页；
- p1–19 是空白页，p20 起才是正文，所以视觉上像「20 页以后才坏」。

修复：`_is_two_up()` 从 PDF 页面宽高比检测版式（抽样 5 页取多数，按文件 mtime 缓存），
竖版忽略 `half` 并走整页缓存。但只有服务端修复还不够：页图响应带
`Cache-Control: max-age=86400`，浏览器会继续用同 URL 的旧「半页图」。
所以 `/api/reading/{code}` 同时返回 `annotated.two_up`，前端只对横版书带
`half=left`；竖版书 URL 不含该参数，旧缓存被 URL 变化自然击穿。
验证：用缓存过旧图的浏览器 profile 重开，GB 50011 请求
`?dpi=220&p=24`（无 half），显示 1287×1819 整页；其余 8 本仍出单联
（GB 50007 p22 = 1287×1776）；pytest 349 条全绿。

## 边界

- 只对**横版 2-up** 标注版做单联裁切；竖版单页与干净版回退保持整页。
- 不要假设一批扫描件同版式：版式必须按文件检测，缓存键带 mtime。
- 若以后出现左右不同页的扫描，必须改为按页映射左右，不能直接 `left`。
- 精读是导航层，不复制、不上传规范原文，仍只显示本机 PDF 渲染页。
