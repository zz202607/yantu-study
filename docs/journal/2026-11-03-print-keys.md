# 2026-11-03 · M12.1 打印键补齐（每个做题入口都能直接出 A4 卷）

## 问题

用户的真实流程是「所有题、每天的任务、复习、做题都打印出来做」。
但打印只藏在错题本「打印卷」和计划页「打印本周任务」两个地方：
首页、复习页、查题查看器、错题详情、训练弹层都没有入口。
打开 App 的第一屏看不到怎么打印，等于默认流程走不通。

## 决定

1. **打印键跟着题走。** 入口放在做题发生的同一屏，而不是集中到一个「打印中心」：
   顶部常驻「打印」；首页「打印出来做」四格；复习页；查题查看器；错题详情；
   限时拆解/认题卡；错题本/计划页保留原入口。
2. **首页四格只放最高频的四件事。** 今日复习卷 / 本周任务卷 / 错题卷（全部未掌握）/
   更多打印选项。错题卷固定按 `status=active` 打全部未掌握，不受上次筛选影响。
3. **复习卷打冻结队列，不打「剩余题」。** 复习会话一旦创建，`session.queue` 就是
   今天的完整队列；用户先点「打印这卷」，再在纸上做完、集中录入，比逐题打更符合
   纸面工作流。服务端沿用 `scope=review` 的会话优先级。
4. **新增 `scope=qids`。** 查看器/详情/训练弹层直接传当前题号列表，不再为每种入口
   新增一个 scope。最多 30 题，与旧 scope 共用同一套排版和缓存。
5. **只收完整题号。** `C3-11` / `A2025-A-13` / `M2-13` 才接受；裸 `3-11` 在案例册
   和知识册都存在，服务端返回 400 而不是默认按 C 册打印。前端传的都是已解析的 qid。
6. **默认不加班封面。** 单题/复习卷直接题面+答案；只有「本周任务」和训练组带
   封面任务单与结果回填格，避免单题也印一整页。
7. **同一时间只生成一份。** 手机端重复点会生成多份大 PDF；统一 `runPrint` 加忙锁，
   按钮显示「生成中…」，完成后恢复原按钮内容。

## 实现

- `app/server.py`
  - `/api/print` 新增 `qids` / `title` 参数；`scope=qids` 校验后构造可选题面列表；
  - 复用 `qid_exists()`（lookup 只读）过滤题库里不存在的题号；
  - `ValueError` 从 500 改为 400（例如所有题面都生成失败）。
- `app/print_export.py`
  - `parse_qid_list(text)`：按中英文逗号、分号、顿号、空白切分，只留完整题号，
    去重保序；单独可测。
- `app/static/index.html`
  - 顶部 `#headerPrint`；首页 `.print-grid` 四张卡；复习 `.review-tools` 加
    `#rPrint`；查看器 `#viewerPrint`（单题/批量文案随 `state.order` 变化）；
    详情 `#dPrint`；训练题的 `.drill-tools` 和结束页 `#drillSummaryPrint`；
  - 抽出 `printSheetQuery / runPrint / printScope / printQids`，旧打印面板改为调用
    同一套；下载文件名按内容命名（`今日复习卷.pdf`、`C3-11.pdf`、`限时拆解卷.pdf`）。
- `tests/test_print_qids.py`：2 条（完整题号保序去重；裸题号/噪声丢弃）。

## 验证

- API：`scope=qids&qids=C3-11,Z1-10` + 封面 → **4 页**（封面 1 + 题面 1 + 答案 2）、
  **20.2 MB**、**7.4 s**、`errors: []`；`qids=3-11,bogus` → **400**，不是 500。
- 单测 **256 条全绿**（新增 2 条）。
- 无头 Chrome 390×844（真实数据），拦截 `/api/print` 只核对 URL：
  - 首页今日复习 → `scope=review`；本周任务 → `scope=plan`；
    错题卷 → `scope=filter&status=active`；
  - 复习页 → `scope=qids` + 冻结队列 **20 题**；
  - 查看器 `C3-11` → `scope=qids&qids=C3-11`；
  - 详情第一行 `A2025-P-24` → `scope=qids&qids=A2025-P-24`；
  - 临时库训练组 → `scope=qids` + 队列 **5 题**、标题「限时拆解卷」；
  - 0 JS 异常、0 横向溢出。
- 打印面板顶部的「当前筛选」在首页未打开错题本时，回退显示
  「未掌握 N 题（全部未掌握）」，不再是「—」。

## 顺手修复：规范页响应头带中文导致 500

后台日志里出现 `/api/standards/page` 的 `UnicodeEncodeError`：`X-Standard` 头写的是
`standard["code"]`，其中 `GB 50021-2001(2009年版)`、`GB∕T 40112-2021` 等 5 条带中文/
全角分隔符。Starlette 用 latin-1 编码 header value，直接抛异常 → 500。

- 改为优先用 ASCII 的 `code_key`，再过 `standards.header_safe()`（`ascii/ignore`）；
- 实测 `code=GB 50021-2001(2009年版)` → **200**，`x-standard: GB50021-2001`，330 页；
- 新增 1 条单测；**257 条全绿**。
- 教训：自定义响应头只放 ASCII；文件名用 `filename=`（Starlette 会做 RFC 5987 编码），
  不要把中文塞进自定义头。

## 限制 / 下一步

- `scope=qids` 不接受裸题号；调用方必须先解析册别（现有前端都满足）。
- 30 题仍需 1–2 分钟；已用忙锁和提示处理，但没有后台任务/进度条。
- 「本周任务卷」仍按原型选题，不是按「今天要做哪几题」的日清单；
  如果以后要日卷，可在计划模块加 day 粒度选题，再复用 `scope=qids`。
- 打印卷仍不做页内跳转/书签；题号在每页页眉，靠纸质翻页即可。
